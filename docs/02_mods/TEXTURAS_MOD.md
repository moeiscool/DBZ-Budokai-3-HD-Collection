# Launcher "Textures" tab — how it works

> How the B3 HD → B3 HD texture mod works from the launcher
> (script `mod center hd/texture_b3.py` + Textures tab in `launcher_state.cpp`).

---

## 1. What it does

It lets you edit a **character's textures** (the DXT3 `.dds` embedded in the
#AMB bin / #AZT block) and generate an **active mod** that replaces them in
game, without touching the geometry (the bin does not change size).

General flow:
1. **Extract** a character's textures as **editable PNGs**.
2. **Edit** the PNGs (in the folder you choose).
3. **Rebuild** the mod: re-encodes the PNGs to DXT3 and generates the mod's AFS.

---

## 2. Tab elements

### 2.1 Character (source of the textures)
Combo with the catalogue `mod center hd/catalog_b3.cat` (183 characters). Each
entry shows `Name [bin N]` to tell variants of the same character apart
(e.g. Dr. Gero `[bin 91]` vs `Dr. Gero (Traje alternativo) [bin 92]`).

> ⚠️ Some bins have NO textures of their own (partial models/variants that
> reuse another bin's, e.g. Dr. Gero's bin 92). The extract warns with a clear
> message instead of failing.

### 2.2 Target slot (where the textures are applied)
- **"The same character (no swap)"** (default): the textures are applied to
  the character they were extracted from.
- **Another character**: the source bin (with its edited textures) is placed
  in the target's slot → compatible with **model swaps**: you extract
  textures from A, edit them and apply them to B's bin (which may come from a
  swap).

### 2.3 Mod name
Defines the mod's folder (`mods/<name>/`). If left empty, `tex_<bin>` is
generated. Characters invalid on Windows (`<>:"|?*`) are sanitised.

### 2.4 Texture folder (PNG)
- **Filled in automatically** when extracting, with the default path
  (`mods/<mod>/textures`).
- **Editable**: you can type any other folder where you are editing.
- **"Browse..."** button: opens the native Windows dialog to choose a folder
  (helper `PickFolder()` in `launcher_state.cpp`, `IFileOpenDialog` +
  `FOS_PICKFOLDERS`).

> The "Rebuild" button is enabled ONLY if the configured folder contains
> `textures_meta.json` (generated by the extract). It does not depend on the
> mod's name.

---

## 3. Buttons

| Button | What it does |
|-------|----------|
| **Extract textures to PNG** | Extracts the bin, finds the #AZT block and writes each texture as an editable PNG into the configured folder. Generates `textures_meta.json` (with each texture's original DDS header). |
| **Open texture folder** | Opens the active folder in Windows Explorer (to view/edit the PNGs). |
| **Rebuild mod with edited textures** | Re-encodes the PNGs to DXT3, rebuilds the DDS (header + bitmap), replaces it in the #AZT, LZX-compresses with `/N:2048`, pads to the slot and generates the active AFS mod. |

---

## 4. #AZT format (summary)

- The #AMB bin → #AWO (model) + #AZT (textures).
- #AZT header: `tex_am` at +0x10, `index_loc` at +0x14 (offset table).
- Each texture: `idx@+0`, `type@+4`, `w@+16`, `h@+18`, `data_off@+0x14`
  (offset relative to the AZT of the 128-byte DDS header + DXT3 bitmap).
- DXT3 bitmap = `w*h` bytes (BC2, 16 B per 4x4 block, mipmaps=0).
- Pillow decodes DXT3 DDS → RGBA; our own DXT3 encoder (numpy) re-encodes to
  the exact size.

## 5. `texture_b3.py` script (CLI)

```
# Extract (default folder: mods/<mod>/textures)
python "mod center hd/texture_b3.py" extract --bin <n> [--mod <name>] [--afs <afs>] [--out <mods>] [--dir <folder>]

# Rebuild
python "mod center hd/texture_b3.py" build --mod <name> [--afs <afs>] [--out <mods>] [--dir <folder>] [--slot <target>]
```

Key arguments:
- `--bin N` (extract): the character's AFS entry.
- `--dir <folder>`: PNG folder (extract: output; build: input). Useful for
  editing outside the mod's tree.
- `--slot N` (build): target slot in the AFS (by default the same bin as the
  extract). Lets you apply one character's textures onto another (swap).
- `--afs <path>`: data_cmn.afs to operate on (default `us/data_cmn.afs`).

The build generates the mod's `manifest.txt` (name/description/type/source/target)
and the rebuilt AFS with **mid-insert** (the bin can grow in its slot without
breaking the AFS table).

## 6. Robustness notes / errors

- **"volume label syntax" error**: it was caused by MSVC's `_popen` + cmd.exe
  when launching Python with a command starting with `"`. Solved by using
  `CreateProcessW` (mod_pipeline.cpp), which launches Python directly without
  cmd.exe.
- **Fixed workdir**: the script uses `out/build/win-amd64-release/.tex_work`
  (it does not depend on the environment's `TEMP`, which the launcher may
  inherit invalid) and passes xbcompress/xbdecompress an environment with
  fixed `TEMP`/`TMP`.
- **Diagnostics**: `RunAsync` writes the exact command to
  `out/build/win-amd64-release/pipeline_cmd.log`; the script dumps any
  traceback to `texture_b3_error.log` and prints the full traceback in the
  launcher's output.
- **Bins without #AZT**: clear warning instead of a traceback (e.g. Dr. Gero
  bin 92).
- The texture tools are not available on the **PS5** build (no launcher);
  texture mods/packs built on PC work there when copied to `/data/dbz3/mods/`.
