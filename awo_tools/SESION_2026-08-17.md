- The guest uses BINARY SEARCH over the table → requires increasing order.

## 2. ❌ WHAT FAILS (documented causes)

### 2.1 The injection deforms (krillin_ps2)
- PS2 and HD local coords do NOT match vertex-for-vertex (HD is a decimated
  REWORK: 0 % match, different per-bone counts).
- The "nearest by local coords" search only pairs well where scale
  corresponds (hands, right arm, upper face).
- 660/1956 slots not covered (bones 36-50 = legs/face that HD does not
  skin in sec34; they go to vb2) keep the original HD positions → mix
  of two systems → deformed.

### 2.2 AFS --append = DISCARDED (host crash 0xC0000005)
- Breaks the AFS table order → the guest's binary search returns
  wrong entries → invalid guest memory read.
- Minidump: dbz3.exe RVA 0xA0967A, `movzbl (%r9,%rax)`.
- The control (original Krillin in append) loaded BY CHANCE (content
  identical to the original).

### 2.3 B1 HD→B3 HD port: bin too large
- B1 AWO = 685856 B (20 AWGs, sec34 10471 + vb2 449 + IB 43026)
  vs B3 = 290784 B (18 AWGs, sec34 4406 + vb2 422 + IB 13510).
- Compressed B1 AMB = 271516 > 106496 slot → truncated → hang.
- B1 skeleton: 52 bones, DIFFERENT ORDER from B3 (OBI/ROBI/LOBI at the end).
  Mapping BY LABEL is mandatory. See AGENTS §3.3.
- To make it fit: decimate the B1 AWO to ~195 KB uncompressed (~290 KB would be
  the B3 size), or use the B1 AZT (262912), which compresses to 37 KB.

> (Later: the virtual mid-insert of 2026-09-09 removed the "must fit in the
> slot" constraint; see `AGENTS.md` §6.)

### 2.6 🔴 FINAL CHECK: VB2 IS THE FACE/LEGS BLOCKER

- **The B3 IB uses vb2 in 789 of 5140 indices (15.4 %)** — the head/face.
- vb2 (226 slots, indices 1956-2181) has its OWN layout:
  `[x, y, z=1.0, 0, 0, ?, ?, nan@+28, nx, ny, nz]` with positions in 0..2
  (NOT the sec34 world space, which spans -6..6). It is a face projection
  buffer with bone=0xFFFFFFFF (no skin).
- **The PS2 injection only touches sec34 → it CANNOT fix head/faces/
  knee/foot** (those live in vb2 + AWGs 1-17). Inherent.
- To fix them: full reconstruction (sec34 + vb2 + IB + arms +
  submesh data) from PS2 — the B1 way. See §6.

## 5. NEXT STEPS (most promising way)

### A. Refine PS2→HD matching (recommended)
Transform PS2 local coords → PS2 world → HD local using the pose matrices
(IDENTICAL 51/51 in both) and look for the HD slot of the SAME bone whose
world position matches. Avoids mixing different scales.

### B. Characters that do NOT exist in HD (IW, Pikkon, Pan, Super 17)
No HD rework to interfere → build the AWO from scratch with the character's
counts. Requires the compressed bin to fit in the slot.

### C. Real B1→B3 port
1. B1→B3 bone mapping BY LABEL (see AGENTS §3.3).
2. Decimate the B1 AWO to ≤~195 KB uncompressed (use analyze_awo_b1.py).
3. Repack the AMB → compress ≤106496 → mid-insert.

### D. NOTE on decimation (Janemba lesson)
Decimation ALONE fixes nothing if the buffer re-layout breaks the IB.
For B1, the AWO already carries its real IB → decimating vertices with IB
remapping is viable (unlike PS2, which carries no explicit IB).

### 6.1 Lessons transferable to B3

1. **The native swap is the PRIMARY way** (validated in B1): the runtime draws
   the complete #AWO/#AMB bin as is (mesh group + IB + bones + UVs). It does not
   validate the slot. In B1, full HD Chaozu (352+353) in the TSH slot = perfect.
   → **B3 already has this validated** (sw_goten_nativo).

2. **Injecting PS2 positions over a host HD bin DEFORMS** (B1 §2,
   B3 RE_PROGRESO §15-19): HD geometry is RE-TOPOLOGIZED (own IB,
   reordered vertices). Nearest-neighbour matching at 98 % still deforms
   arms/hands/head/legs. → **Confirmed in B3**: v5 (1296 slots)
   deforms; v7 with threshold (197 slots) is the injection limit.

3. **The right way for a PS2→HD port = REBUILD the COMPLETE bin**:
   sec34 (44 B) + IB + arms + **submesh data zone** regenerated from
   PS2. Do NOT inject over the host.

4. **🔴 SUBMESH DATA = the missing piece (decoded in B1)**:
   between the arms zone and the sec34 of each HD AWG there is a zone of
   **submesh descriptors** (one per mesh part):
   ```
   +00..+5F transform/material floats
   +60 c08 = range A start (contiguous between descriptors)
   +64 c0C = range A size
   +68 c10 = range B start
   +6C c14 = range B size
   +70 label 16 B (X??_BODY, ??_L01_LHAND...)
   +80 debug string "max N m" (from the developer)
   ```
   **Risk**: copying a template's submesh zone over new geometry
   → **hang** (offsets that do not match). One descriptor must be GENERATED
   per PS2 mesh part with the ranges of the new buffers.

5. **🔴 B3 ALSO HAS THE SUBMESH DATA ZONE** (verified today):
   labels `XKLL_BODY`, `KLL_L00_LHAND`, `KLL_L00_RHAND`, `XKLL_M_DTEETH`,
   `XKLL_M_UTEETH`, `XKLL_L00_FACE` + `max N m` strings at 0x2D61-0x3471
   (AWG0) and in each hand/face AWG. BUT the field offsets
   (c08/c0C/c10/c14) are NOT at +0x60 as in B1 — the B3 layout differs.
   **Pending**: map the exact B3 descriptor layout.
   (Later: mapped in AGENTS §3.4.8 — A/B ranges at +0x50..+0x5C.)

6. **B2 PS2 skeleton = HD 1:1** (verified with Tenshinhan in B1): same
   labels in the same order (the first 42). → In B3 the same applies to
   IW/B2/B3 characters with a different costume: use the native HD bin of the
   same character as a STRUCTURAL TEMPLATE (axes, arms, mesh headers, submesh
   data) and replace only the geometry.

7. **GAMECUBE = DISCARDED for model swaps**: the B1 GC ISO uses different
   `#ACO/#ACB/#AMB` formats (`#AMO0` PS2 vs `#AWO` HD). Use ONLY the PS2 AFS
   as a source.

8. **External models (EMD/FBX)** → B1 uses `obj_to_awg_hd.py` +
   `build_awg_hd_full.py` (OBJ→AWG HD retopology) + pose retargeting
   (`inv_rigid`). The community solves this with manual 3D retopology
   (OBJ→AMG + Blender + Model Rig Toolset). In B3, the SDBH EMD→FBX→JSON
   pipeline already exists (`mod center hd/`) but failed on pose retargeting
   (skeletons with a different axis convention).

### 6.2 REAL roadmap for adding characters to B3

Based on the methodology validated in B1 (SESION11 §7):

1. **Catalog**: scan the PS2 AFS (B1/B2/B3/IW) for `X??_BODY` labels
   (scanning the whole AMO, not just the start).
2. **Native swap** for characters that already exist in HD (B3→B3): done.
3. **PS2→HD port only for characters WITHOUT an HD version** (IW: Pikkon, Pan,
   Super 17, Janemba...): FULL RECONSTRUCTION:
   a. Extract #AMO0 from the PS2 AFS + parse mesh parts/verts/rig.
   b. Verify the skeleton is 1:1 with the HD host character (labels).
   c. Use the native HD bin of the SAME skeleton as a structural template.
   d. **Rebuild sec34 (44 B) + IB from the PS2 triangles** (FaceType).
   e. Regenerate arms (IB ranges per bone).
   f. **Regenerate the submesh data zone** (descriptors per mesh part)
      — PENDING: map the B3 descriptor layout.
   g. Convert the PS2 #AMT texture → HD #AZT.
   h. Compress ≤106496 → mid-insert → validate in battle.
4. **Test character** before automating: in B1 it was B2 PS2 Tenshinhan
   (1:1 skeleton, different costume). For B3: **Pikkon or Pan from IW** (they
   exist in `modding resources\All Character Models from IW into AMB format\`).
